# Codex Web 会话管理需求文档

## 1. 背景

当前 Codex CLI 的会话主要通过终端使用。用户希望增加一个本机 Web 管理界面，用于查看 Codex 历史会话、恢复指定会话，并在浏览器中继续任务。

系统应优先复用 Codex CLI 已有能力，尤其是原生 `resume` 能力，不重新设计 Codex 会话协议或替代 Codex CLI 的核心执行逻辑。

## 2. 目标

构建一个 Codex Web 管理台，满足以下目标：

- 读取默认 Codex 会话目录 `~/.codex/sessions`。
- 展示 Codex 会话列表和会话详情。
- 通过 Codex CLI 原生 `resume` 能力恢复指定会话。
- 在 Web 页面中继续输入任务并实时查看 Codex 输出。
- 展示命令执行过程。
- 支持 Codex CLI 审批交互，包括允许和拒绝。
- 提供一个默认密码登录能力。
- 支持本机和局域网访问。

## 3. 使用范围

### 3.1 目标用户

MVP 面向单用户使用。典型场景是用户在自己的开发机或局域网内服务器上启动 Web 管理台，然后通过浏览器管理 Codex 会话。

### 3.2 访问方式

- 默认可配置监听地址。
- 允许局域网访问。
- 建议默认监听地址为 `0.0.0.0` 或通过配置显式开启。
- 必须提供登录保护，避免局域网内未授权用户直接访问。

### 3.3 会话来源

会话数据目录固定以 Codex 默认目录为准：

```text
~/.codex/sessions
```

MVP 不设计独立会话存储格式。系统可以建立少量 Web 管理端自身状态，例如登录 session、运行中进程状态、UI 展示缓存，但 Codex 历史会话仍以原生文件为准。

## 4. 功能需求

### 4.1 登录

进入 Web 管理台时必须先登录。

需求：

- 提供登录页面。
- 使用单个默认密码。
- 默认密码通过环境变量 `CODEX_WEB_PASSWORD` 配置。
- 如果环境变量未配置，默认密码为 `admin`。
- 登录成功后创建 Web 登录态。
- 未登录用户访问 `GET /api/me` 时应返回 `authenticated: false`，用于前端渲染登录页，不应返回 401。
- 未登录用户不能访问会话列表、会话详情、恢复接口、审批接口、运行状态接口和配置接口。
- 提供明确可见的登出能力，登出后应清除登录态并回到未登录状态。

安全要求：

- 页面应提示用户修改默认密码。
- 生产或局域网长期使用时，不建议继续使用 `admin`。
- 登录态应设置合理过期时间。

### 4.2 会话列表

系统需要读取 `~/.codex/sessions` 并展示会话列表。

每条会话至少展示：

- 会话 ID。
- 标题或摘要。
- 备注标题，如果用户已设置。
- 创建时间。
- 最近更新时间。
- 工作目录。
- 当前状态。

状态包括：

- 历史会话。
- 恢复中。
- 运行中。
- 等待用户输入。
- 等待审批。
- 已结束。
- 失败。

列表能力：

- 默认按最近更新时间倒序排列。
- 支持关键词搜索。
- 搜索范围至少包括会话 ID、备注标题、标题或摘要、工作目录。
- 支持为会话设置备注标题，备注标题仅作为 Web 管理台展示元数据，不修改 Codex 原始会话文件。
- 不允许删除历史会话。
- MVP 不要求归档、标签、批量操作。

标题和摘要生成规则：

- 如果用户设置了备注标题，列表主标题优先使用备注标题。
- 如果没有备注标题且 Codex 会话文件中有标题，使用 Codex 标题。
- 如果没有标题，使用首条用户消息生成摘要。
- 如果无法解析消息，使用会话文件名或会话 ID 作为兜底展示。
- 备注标题应可编辑和清空，清空后恢复为 Codex 标题或摘要兜底。

### 4.3 会话详情

用户点击会话后进入详情页。

详情页展示：

- 会话 ID。
- 工作目录。
- 创建时间和最近更新时间。
- 模型信息，如果会话记录中可读取。
- sandbox 配置，如果会话记录中可读取。
- approval 策略，如果会话记录中可读取。
- 历史消息。
- 工具调用或命令执行记录。
- 当前恢复进程状态，如果该会话正在运行。

消息展示要求：

- 区分用户、Codex、系统消息、工具输出、审批记录。
- 保留消息时间，如果可读取。
- 长文本支持折叠。
- 长命令输出支持折叠或截断。
- 不修改原始会话历史。

### 4.4 恢复会话

用户可以在会话详情页恢复指定会话。

恢复方式：

- 后端调用 Codex CLI 原生 `resume` 能力。
- Codex CLI 路径默认使用系统 `PATH` 中的 `codex`。
- Codex CLI 路径应支持配置。

并发规则：

- 允许同时恢复多个不同会话。
- 同一个会话同一时间只允许一个活跃恢复进程。
- 如果用户重复恢复已经运行中的同一会话，应返回当前运行状态，而不是启动第二个进程。

恢复状态：

- 启动中。
- 运行中。
- 等待输入。
- 等待审批。
- 已退出。
- 启动失败。

失败处理：

- 如果 Codex CLI 不存在，应提示配置 CLI 路径。
- 如果会话文件不存在或无法解析，应展示明确错误。
- 如果 `resume` 命令启动失败，应展示退出码和错误输出。

### 4.5 继续任务

恢复会话后，用户可以在 Web 输入框继续发送新任务。

需求：

- 输入框支持发送普通文本指令。
- 后端将用户输入发送给对应 Codex CLI 进程。
- 前端实时展示 Codex 输出。
- 支持多会话并发时按会话隔离输入和输出。
- 当前会话未恢复时，输入框应不可发送或提示先恢复。

运行状态：

- 空闲。
- 运行中。
- 等待用户输入。
- 等待审批。
- 完成。
- 失败。

### 4.6 实时输出

Web 页面需要实时展示 Codex 运行输出。

建议使用 WebSocket 或 Server-Sent Events。

展示内容：

- Codex 文本回复。
- 命令执行开始。
- 命令执行输出。
- 命令执行结束。
- 审批请求。
- 错误信息。
- 进程退出状态。

输出要求：

- 不同会话的输出必须隔离。
- 刷新页面后可以重新连接正在运行的会话。
- 对大量输出做限流、截断或折叠，避免页面卡死。

### 4.7 命令执行过程展示

当 Codex 执行命令时，Web 端应展示命令执行过程。

每条命令记录应尽量包含：

- 命令内容。
- 工作目录。
- 开始时间。
- 结束时间。
- 运行状态。
- 标准输出。
- 标准错误。
- 退出码。

状态包括：

- 等待执行。
- 执行中。
- 成功。
- 失败。
- 被拒绝。
- 被取消。

UI 要求：

- 正在执行的命令应有明显状态。
- stdout 和 stderr 应可区分。
- 长输出默认折叠。
- 支持复制命令内容。

### 4.8 审批交互

当 Codex CLI 请求审批时，Web 页面应展示审批卡片。

审批卡片至少包含：

- 审批类型。
- 请求原因。
- 待执行命令或操作。
- 工作目录。
- 风险提示。
- 允许按钮。
- 拒绝按钮。

审批行为：

- 用户点击允许后，将审批结果传回 Codex CLI。
- 用户点击拒绝后，将拒绝结果传回 Codex CLI。
- 审批结果应记录在当前 Web 运行状态中，并展示在会话详情里。
- 同一审批请求只能处理一次。

实现要求：

- 如果 Codex CLI 提供结构化审批事件，应优先使用结构化事件。
- 如果 Codex CLI 只提供终端交互式提示，后端需要解析输出并向 stdin 写入用户选择。
- 文本解析方案必须隔离在适配层，避免散落在业务逻辑中。

### 4.9 设置

MVP 至少支持以下配置：

- Web 监听地址。
- Web 监听端口。
- 默认密码。
- Codex CLI 路径。
- Codex 会话目录。

默认值：

```text
监听地址: 0.0.0.0
监听端口: 3000
默认密码: 环境变量 CODEX_WEB_PASSWORD，未设置时为 admin
Codex CLI: codex
会话目录: ~/.codex/sessions
```

会话目录虽然允许配置，但默认必须使用 `~/.codex/sessions`。

## 5. 非功能需求

### 5.1 安全

- 所有管理页面和接口必须要求登录。
- 默认密码为 `admin` 时，应在 UI 中提示风险。
- 局域网访问场景下，建议用户配置强密码。
- 后端不能提供删除 `~/.codex/sessions` 历史文件的接口。
- 后端不应暴露任意文件读取接口。
- 命令审批必须由已登录用户显式确认。

### 5.2 稳定性

- 后端应跟踪每个 Codex 子进程状态。
- 子进程退出后应清理运行状态。
- WebSocket 或 SSE 断开不应直接杀死 Codex 进程。
- 页面刷新后应能重新看到当前会话的运行状态。

### 5.3 可维护性

建议将系统拆分为以下模块：

- 会话扫描模块：读取和解析 `~/.codex/sessions`。
- Codex CLI 适配模块：封装 `resume`、stdin、stdout、stderr、审批交互。
- 运行进程管理模块：管理多会话并发恢复。
- Web API 模块：提供登录、列表、详情、恢复、输入、审批接口。
- 实时事件模块：WebSocket 或 SSE。
- 前端页面模块：列表、详情、登录、设置。

### 5.4 兼容性

- 应兼容 Codex 默认会话目录结构。
- 对无法解析的新旧格式会话文件，应降级展示基础文件信息。
- 不应依赖脆弱的固定终端颜色或 ANSI 样式解析。
- 如果 Codex CLI 支持 JSON 或结构化输出，应优先使用。

## 6. 页面需求

### 6.1 登录页

元素：

- 密码输入框。
- 登录按钮。
- 默认密码风险提示。

行为：

- 密码错误时展示错误。
- 登录成功后跳转会话列表页。

### 6.2 会话列表页

元素：

- 顶部状态栏。
- 搜索框。
- 会话列表。
- 备注标题编辑入口。
- 设置入口。
- 登出按钮。

列表项展示：

- 摘要。
- 最近更新时间。
- 工作目录。
- 状态。

行为：

- 点击列表项进入详情页。
- 支持搜索过滤。
- 支持设置、修改和清空备注标题。
- H5 移动端默认收起会话列表，以侧边栏或抽屉形式承载。
- 用户点击会话列表按钮后展示会话列表。
- H5 会话列表抽屉内必须保留搜索能力。
- 不提供删除按钮。

### 6.3 会话详情页

元素：

- 会话元信息。
- 恢复按钮。
- 当前运行状态。
- 历史消息区域。
- 实时输出区域。
- 命令执行区域。
- 审批卡片。
- 输入框。

行为：

- 未恢复时可以查看历史，但不能继续输入。
- 点击恢复后启动 Codex CLI `resume`。
- 运行中实时追加输出。
- 等待审批时展示审批卡片。
- 审批完成后继续展示 Codex 输出。

### 6.4 设置页

元素：

- 监听地址。
- 监听端口。
- Codex CLI 路径。
- 会话目录。
- 密码配置说明。

MVP 中设置页可以只展示当前配置，不一定支持在线修改。

## 7. API 需求草案

具体实现可调整，但建议至少包含以下接口。

认证：

- `POST /api/login`
- `POST /api/logout`
- `GET /api/me`

说明：`GET /api/me` 是认证状态探测接口，允许未登录访问并返回 `authenticated: false`；其他管理接口仍必须要求登录。

会话：

- `GET /api/sessions`
- `GET /api/sessions/:id`
- `PATCH /api/sessions/:id/metadata`

运行：

- `POST /api/sessions/:id/resume`
- `POST /api/sessions/:id/input`
- `POST /api/sessions/:id/approval`
- `GET /api/sessions/:id/runtime`

实时事件：

- `GET /api/sessions/:id/events`

如果使用 WebSocket，可以替换为：

- `WS /api/sessions/:id/ws`

## 9. MVP 范围

MVP 必须完成：

- 单密码登录。
- 读取 `~/.codex/sessions`。
- 会话列表。
- H5 侧边栏/抽屉式会话列表。
- 会话备注标题。
- 会话详情。
- 调用 Codex CLI 原生 `resume`。
- Web 输入继续任务。
- 实时展示 Codex 输出。
- 展示命令执行过程。
- 支持审批允许和拒绝。
- 支持多个不同会话同时恢复。
- 禁止删除历史会话。

MVP 暂不包含：

- 多用户账号体系。
- 角色权限。
- 公网部署支持。
- 历史会话删除。
- 会话标签。
- 会话归档。
- 全文索引搜索。
- 多机器同步。
- 替代 Codex CLI 的自定义执行协议。

## 10. 实现假设和风险

### 10.1 实现假设

- Codex CLI 已安装并可通过 `codex` 命令调用。
- Codex CLI 支持通过命令行恢复指定历史会话。
- 后端可以通过子进程管理 Codex CLI。
- 用户输入可以通过 stdin 传递给 Codex CLI。
- Codex 输出可以从 stdout 和 stderr 捕获。

### 10.2 主要风险

- Codex CLI 的 `resume` 交互协议如果不是稳定的结构化协议，审批解析可能脆弱。
- 不同版本 Codex CLI 的会话文件格式可能变化。
- 多会话并发运行时可能同时修改同一 workspace，需要 UI 提示用户注意。
- 局域网访问依赖单密码保护，密码过弱会有安全风险。
- 长输出和大量事件可能导致前端性能问题。

### 10.3 风险缓解

- 优先使用 Codex CLI 的结构化输出能力。
- 将 CLI 文本解析封装在独立适配层。
- 会话解析失败时降级展示文件基础信息。
- UI 显示每个会话的 workspace，提示用户避免多个会话同时操作同一目录。
- 默认提示修改 `admin` 密码。
- 对输出做截断、折叠和事件缓存上限。

## 11. 验收标准

MVP 验收时应满足：

- 未登录打开 Web 时能看到登录页和登录按钮。
- 使用正确密码可以登录，错误密码不能登录。
- 登录后能看到明确的登出按钮。
- 登出后登录态被清除，管理接口重新拒绝访问。
- 能读取并展示 `~/.codex/sessions` 中的历史会话。
- 会话列表按最近更新时间倒序展示。
- H5 移动端会话列表默认收起，点击后以侧边栏或抽屉展示，并支持搜索。
- 可以设置、修改和清空会话备注标题。
- 可以进入会话详情查看历史消息和元信息。
- 可以点击恢复并启动 Codex CLI 原生 `resume`。
- 可以在 Web 中向恢复后的会话发送新任务。
- 可以实时看到 Codex 回复和命令输出。
- Codex 请求审批时，Web 能展示审批请求。
- 点击允许或拒绝后，Codex CLI 能收到对应结果。
- 可以同时恢复多个不同会话。
- 同一会话不能被重复启动多个活跃恢复进程。
- Web 不提供删除历史会话能力。
- 未登录访问管理接口会被拒绝，`GET /api/me` 认证状态探测接口除外。
