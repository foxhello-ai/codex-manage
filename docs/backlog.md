# Backlog

## CM-B-001: 移动端界面超出手机视窗

### 状态

- 提出日期：2026-07-21
- 状态：已实现，待移动端真实视口回归
- 优先级：中

### 背景

Codex Manage 明确要求支持 H5 移动端使用。当前移动端已经有会话列表抽屉、移动运行状态、详情页和审批操作等适配设计，但实际使用中仍出现界面内容没有完整落在手机视窗内的问题。

### 问题现象

用户在手机视窗中打开当前会话页面时，可以复现界面超出手机视窗的问题。表现为页面内容被挤压、底部或主体区域高度不符合视窗、部分内容需要异常滚动或无法在当前手机视口内自然查看。

该问题属于 Codex Manage 项目，不属于 Code Workspace。

### 初步原因

待实现时重新用移动端视口截图确认。当前根据代码和现象初步判断，风险点包括：

- 移动端详情页使用 `100dvh` 相关高度计算，同时还叠加移动运行状态区域。
- `.appShell.reserveFloatingStatus .sessionDetail` 在移动端设置了固定 `height` 和 `min-height`，小屏高度下可能撑破视窗。
- 移动运行状态展开后继续压缩详情区，可能与输入区、工具栏或浏览器动态地址栏产生高度冲突。
- 部分工具栏、运行状态标签、审批操作或长标题在窄屏下可能没有充分换行或收纳。
- 移动端已隐藏桌面会话列表，但详情页内部仍可能存在局部固定高度和滚动容器冲突。

### 影响范围

后续处理需要重点检查以下区域：

- `src/client/styles.css` 中移动端断点下的 `.appShell`、`.sessionDetail`、`.detailStack`、`.detailScrollContent`。
- `src/client/styles.css` 中 `.mobileRuntimeStatus`、`.mobileRuntimeSummary`、`.mobileRuntimeDetails`。
- `src/client/App.tsx` 中移动端会话详情和运行状态渲染逻辑。
- 底部输入区、审批面板、命令输出和会话详情滚动容器之间的高度关系。
- Playwright mobile 项目的视口验收。

### 建议方案

1. 用 Playwright mobile 项目复现并保存截图，明确是横向溢出、纵向撑破，还是固定高度计算错误。
2. 移动端避免给详情区设置不可压缩的 `min-height`，改为 `minmax(0, 1fr)` 和内部滚动。
3. 将移动运行状态、详情滚动区、输入区拆成明确的 grid/flex 层级，保证总高度不超过 `100dvh`。
4. 对长标题、权限标签、审批数量和工具栏按钮补充换行、截断或菜单收纳策略。
5. 在 mobile e2e 中增加无横向溢出和关键区域在视窗内的断言。

### 验收标准

- 在 375x812、390x844、430x932 手机视窗下，当前会话页面没有横向溢出。
- 移动端会话详情、运行状态和输入区都在手机视窗内形成稳定布局。
- 展开和收起移动运行状态后，详情区不会被挤出视窗。
- 会话标题很长时不会撑破顶部或详情布局。
- 审批面板、命令输出和输入区在移动端可滚动、可操作。
- Playwright mobile 项目有对应截图或断言覆盖。

### 实现记录（2026-07-25）

- 已调整 `src/client/styles.css` 移动端布局：应用壳、内容区和会话详情改为 `minmax(0, 1fr)` 可压缩滚动结构。
- 已移除移动端 `.sessionDetail` 固定 `height` 和不可压缩 `min-height`，避免小屏被撑破。
- 已限制展开态移动运行状态高度，并让详情内容在视窗内滚动。
- 已增加移动端横向溢出保护。
- 已通过 `npm run typecheck:all` 和 `npm run build:all`；仍需 375x812、390x844、430x932 视口截图验收。
