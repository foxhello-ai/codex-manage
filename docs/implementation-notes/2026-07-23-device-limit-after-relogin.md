# 退出后重新登录触发设备数量上限

| 跟踪项 | 内容 |
| --- | --- |
| 故障编号 | `CM-INC-20260723-002` |
| 日期 | 2026-07-23 |
| 状态 | 修复已验证、待同步部署 |
| 严重程度 | 高：免费套餐用户退出后无法在同一设备重新登录 |
| 影响范围 | 桌面账号退出、重新登录、设备注册和免费套餐设备上限 |
| 修复分支 | `feature/f-20260721-desktop` |

## 现象

用户在已绑定设备上退出平台账号，再使用相同账号登录时，桌面端提示：

```text
Error invoking remote method 'desktop:login-account':
Error: 已达到当前套餐的设备数量上限
```

服务端错误码为 `DEVICE_LIMIT_REACHED`，HTTP 状态为 409。

## 已确认根因

免费套餐权益 `device.max_count` 为 1。普通退出会删除包含 `deviceId` 和 `deviceCredential` 的本地加密会话，但不会撤销服务端 `active` 设备。重新登录后客户端无法识别原设备，会再次调用设备注册接口；服务端看到已有一台活动设备，因此拒绝创建第二台设备。

“退出平台账号”和“解绑当前设备”是两个不同动作：普通退出不应撤销设备、Tunnel 或域名，因此不能通过退出时自动解绑来规避问题。

## 修复方案

1. 将用户登录 Session 与设备绑定凭据分开加密保存。
2. 普通退出只删除用户 Session，保留当前用户的设备绑定。
3. 同一用户重新登录时恢复 `deviceId` 和 `deviceCredential`，通过凭据交换取得新的设备访问 Token。
4. 只有明确执行“解绑当前设备”时，才撤销服务端设备并删除本地绑定。
5. 若服务端返回 `DEVICE_CREDENTIAL_INVALID`，清理失效绑定并在设备名额允许时重新注册。
6. 启动时将旧版加密 Session 中已有的设备信息自动迁移到独立绑定文件，保证升级后第一次退出不丢失绑定。
7. 增加退出、重新登录后设备注册次数仍为 1 的 Electron E2E 回归断言。

## 验收标准

- 同一账号在同一桌面安装中退出后重新登录成功。
- 重新登录不再次调用 `POST /v1/devices`。
- 重启桌面应用后，设备绑定仍可恢复。
- 不同账号之间不复用设备绑定。
- 点击“解绑当前设备”后，本地绑定和服务端设备同时撤销。
- 设备凭据被服务端撤销后，客户端可以清理失效绑定并按规则重新注册。

## 临时恢复方式

修复版发布前，可在管理后台的“设备管理”中停用旧设备，释放免费套餐的活动设备名额，再重新登录。
