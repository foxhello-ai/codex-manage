# 桌面会话同步、途中交互与 CI 迁移需求

批准日期：2026-11-12。用户已批准本会话中的问题分析与修复范围，并要求先记录需求，再实施。基线：`main@e3b4986`；实施分支：`codex/desktop-interaction-sync`。已合并 main 并发布 v1.0.10，版本、tag 与安装记录见 [发布证据](acceptance/2026-11-12-runtime-v1.0.10/README.md)。

## 用户问题与目标

1. 官方桌面正在执行的会话，在 Manage Web 打开很慢。
2. Manage Web 自身能收到审批，但审批面板需要多次点击或反复打开才出现；不要求 Web 代答官方桌面的权限审批。
3. 会话途中要求人确认、选择方案或补充信息时，Web 只显示运行中，没有问题、选项或答复入口。
4. 将可运行于 Linux 的 GitHub Actions 任务迁移到 instabox，保留 macOS 实机安装验证。

用户截图补充明确了第 3 项：必须识别“执行途中正在等用户回答”，展示完整问题并将答案交回原请求，随后原会话继续。不能以能看到最终历史消息代替途中交互验收。最新截图及原桌面实时状态已确认：该场景为 request_user_input_async 异步问题卡，不能混同同步 request_user_input RPC 或 MCP 表单。

### 用户补充确认（2026-11-12）

- 保留桌面原图标、原启动方式和当前私有后台；不采用改变启动连接的共享服务方案。
- 第 2 项是 Web 自身审批面板的显示与恢复问题，按此口径标为“已实现”，已随 v1.0.10 合并发布。
- 第 3 项确认是独立的问题/选项面板，需要点击提交；接受以文字作为答案，但不能把下一轮聊天入队当成当前问题已答复。已从真实桌面状态确认该卡属于异步问答。
- Web 停止桌面任务、修改桌面执行模型或权限维持现状，不纳入新增修复。
- [途中问答通道说明](implementation-notes/2026-11-12-question-reply-alternatives.md) 记录同步/异步区别及原桌面现有 IPC 方案；使用独立验收服务测试。

### 双端交互的共同要求

- Web 提示具体正在等待什么，并显示可回答的问题；仅显示“运行中”不满足要求。
- 答案按实际交互类型发送：同步请求回复原 RPC；异步问题通过原桌面投递带 questionItemId 的当前 turn 输入。不能把下一轮普通聊天排队当成已答复。
- 任一端回答后另一端清理；重复提交、旧请求及过期回复必须得到明确结果。
- 请求类型需从真实协议记录辨认，区分权限审批、标准问答、MCP 表单与桌面专用交互。
- 保留现有主/子用户授权与桌面文字投递限制，查看不得获取会话写锁。

## 修复前确认的分析证据

- 当前实现使用原生文字队列加持久历史读取，不共享桌面实时 RPC。此前验收明确把桌面审批等操作留在桌面。
- 本地同一会话摘要约 116ms，完整历史约 2062ms，重复完整读取约 1976ms；运行态约 13ms。独立读取分解：`thread/read` 约 1033ms，`thread/turns/list` 约 781ms，模型记录解析约 65ms。更长时间卡顿尚未复现。
- 隔离浏览器复现：HTTP 序号 11 先到、WebSocket 序号 10 的审批快照后到时，页面只显示“正在加载审批请求”；同为序号 11 时可展示问题。
- 内存协议复现：`mcpServer/elicitation/request` 当前收到空对象回复、没有待交互记录。
- 标准问答当前四种审批按钮均发送相同答案，包括拒绝与取消，界面动作与实际回复语义不一致。
- instabox 当前 workspace 可用 `instabox-medium`，其他仓库有 CI 成功记录；不等于本仓库授权与系统安装验证已通过。

1. 不修改官方桌面安装包、启动入口或环境变量，不代答既有业务问题；跨端测试只使用新建的专用验收问题，不要求使用共享 4500 服务。

3. 实现 DSI-06 的可审查工作流改动，保留 macOS。首次试跑需要目标仓库已授权；不能把别的仓库成功记录当作本仓库结果。
4. 在独立 worktree 修改；不重启当前用户服务。隔离测试使用单独端口、临时 profile 和本地模型桩。
5. 对公开仓库，未来如启用 fork PR 工作流，instabox 也会消耗 workspace 配额；需采用 GitHub 外部贡献者审批设置。当前工作流只由 push/manual 触发。
