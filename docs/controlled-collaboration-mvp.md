# 受控协作用户与会话授权（MVP）

- Linear 总需求：[FOX-21](https://linear.app/foxhello/issue/FOX-21/mvp-受控协作用户会话授权与-workspace-隔离)
- 状态：Backlog；尚未纳入目标发布版本
- 最后确认：2026-08-13

## 目标

让主用户能够新增子用户，并只授权其使用指定的既有 Codex 会话。子用户可在被授权会话原始绑定的工程目录中继续使用 Codex，但不得访问或改动其他工程目录。

这是最小协作闭环，不引入完整组织、租户、邀请或细粒度权限系统。

## 最小范围

- 主用户可新增、停用子用户；首版采用本地账号和初始登录凭证。
- 主用户可为子用户授权、撤销一个或多个既有会话。
- 子用户登录后仅能看见和继续获授权会话；不能新建会话、切换 workspace、管理用户/授权或修改全局设置。
- 每个授权会话固定沿用既有 `workspace`。
- 子用户可在获授权 workspace 内按默认审批策略使用 Codex，包括创建、编辑和删除该目录中的文件。
- 主用户撤销授权或停用子用户后，子用户不得继续访问相关会话。

## 安全约束

前端隐藏不是授权边界。服务端须在会话列表、详情、命令、运行态、WebSocket、恢复、输入、模型更新和审批等全部入口校验用户与会话授权。

对子用户：

- 强制使用默认受控权限模式，禁止 `full_access`、`danger-full-access` 和绕过审批。
- 运行时将授权会话的原始 `workspace` 作为固定文件访问范围；workspace 外的读取、创建、编辑、删除和执行请求均应拒绝。
- 保留产品已有的受控能力：发送消息、查看输出、默认审批、允许的模型选择；不授予任意宿主机命令或完全权限。

## 最小数据关系

- `users`：子用户关联其 `owner_user_id`，并记录启用状态与登录凭证。
- `session_grants`：`child_user_id + session_id`；会话的原始 workspace 来自既有会话元数据，不允许子用户覆盖。

不建设通用 RBAC、组织/租户、多主用户共享、转授权或单文件 ACL。

## 非目标

- 邀请邮件、邮箱激活、复杂成员管理或审计报表。
- 子用户创建会话、创建独立 workspace、转授权。
- 多主用户共享同一子用户。
- 文件、命令或时间窗级别的细粒度授权。
- 自动纳入 Desktop / Cloud Platform v1.0.7；进入版本时再关联相应 Release。

## 验收总则

1. 主用户可创建或停用子用户，并为其授权或撤销指定会话。
2. 子用户只可访问已授权会话；授权撤销或停用立即影响后续访问。
3. 子用户在授权 workspace 内可以按默认审批策略正常工作。
4. 子用户不能借由界面、HTTP 或 WebSocket 取得未授权会话、workspace 外访问或完全权限。
5. 最小流程有可重复的自动化测试覆盖。
