# 桌面原会话续聊与写入权交接验收

日期：2026-11-03。实现分支：`codex/desktop-session-handoff`，基于实施开始时最新的 `origin/main`（`68a5284b915aa5930c4f85dd8b7502d3d5d3c3af`）。

## 结论

已安装官方桌面保持自身私有 stdio 后台，Manage 可将文字投递到桌面打开的同一 thread，并自动显示已保存的消息与回答。Manage 自己完成一轮后确认卸载，桌面随后可恢复原 thread、保留上下文继续。本机测试无需共享端口、桌面启动适配器或修改桌面安装包。

当桌面在 Manage 仍执行时打开该会话，会显示“已在另一个应用中打开”。本次在 Manage 释放后等待 10 秒未观察到桌面自动恢复；重新打开原会话后成功继续。不能承诺原版桌面的错误页面会自动重试。

双端实机使用桌面 `26.1002.52244`、内置 CLI `0.162.0-alpha.2`。原始机器上已有桌面与后台未被终止；测试使用独立 profile、临时 `CODEX_HOME` 和工作目录、本地 SSE 模拟模型，不使用真实会话、真实凭据或真实推理。

实机检查包含：

1. 桌面自有后台采用原有 stdio 方式，未配置共享服务。
2. 桌面创建并持有原会话，Manage UI 返回 HTTP 202 和 queued 状态。
3. 桌面消费外部消息后生成回复，原后台 PID 不变。
4. 桌面主动继续时，模型输入包含此前双方问答。
5. 桌面执行慢回合期间，Manage 追加消息有序消费。
6. 两条投递按原生 client ID 对账为 completed，桌面新消息自动同步到 Manage。
7. 同一 thread 内 5 组用户消息和回答均恰好一份。
8. Manage 新建空会话等待超过卸载间隔后，首条输入仍可成功发送。
9. Manage 持续执行时，桌面原会话出现 active writer 错误。
10. Manage 完成后自动释放；桌面重新打开同一 ID 并继续，模型输入保留先前问答。
11. 测试清理后，原有桌面及其直接后台保持存活。

“17 项”按脚本中的独立断言计数，上述列表按用户流程合并展示。

## 限制与实施调整

- 原生冷读取可能在桌面尚未落盘时返回 interrupted。该结果保持待确认并继续对账，不立即判定最终失败。
- 官方后台未保存首轮的新建空会话被卸载后无法 resume。本实现保留该空会话的占用直到首轮完成，避免丢失原 ID；此情况不宣称已释放。
- 仅覆盖本机本地 Codex/Work thread，普通 ChatGPT 云端聊天不适用。双方须使用相同数据目录和兼容的原生队列能力。
- 桌面队列只开放主用户文字；桌面侧审批、停止、模型、权限和附件仍在桌面操作。
- 目标未加载、桌面退出或不消费队列时，保持等待/结果待确认，不自动复制历史或重发。
- 此验收使用模拟文本，不能替代真实工程工具副作用、跨版本或发布部署验收。完整共享桌面私有 RPC 服务继续作为独立研究项。
