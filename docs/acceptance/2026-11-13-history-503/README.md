# 会话历史 503、空白加载与错误提示

## 说明原因

已确认界面缺陷：首屏将详情与历史绑定，历史 RPC 等待时无法先显示独立详情；历史区要求 detail 存在才显示加载提示；后台刷新开始就清除错误，使错误只短暂出现。本机同一活动会话的最近 20 轮原始 RPC 数据约 11 MB。

**用户实际 503 的根因待验证。** 本机详情元信息 128～133ms、历史 857～3020ms 均成功，没有捕获实际 503。源码默认 RPC 超时为 60 秒，异常被统一转为 HTTP 503；这只是已确认的代码路径，不能据此断定用户这次一定是超时，也不能断言是桌面升级或会话锁。

## 当前代码问题点

- 分页按轮数限制，不按条目或字节限制；20 轮依然包含所有工具记录。直接改 summary 会漏掉已展示的消息、文件改动与中间过程，本次保留完整历史语义。
- 错误在自动请求开始时消失；详情缺失时没有历史加载提示和明确重试入口。
- 原详情失败日志只有 HTTP 503 和整体响应时间，缺少对应失败原因。

## 代码错误位置

- src/client/App.tsx：loadSessionDetail、refreshCurrentSession、SessionDetailPanel。
- src/server/services/SessionService.ts：readSessionDetail 的 thread/turns/list（itemsView=full）。
- src/server/services/CodexAppServerClient.ts：默认 60 秒请求超时。
- src/server/routes/sessions.ts：详情异常转换为 503。

## 修改方案

先显示元信息，历史独立加载；保留失败提示到请求成功，提供重试；失败刷新保留已加载消息；服务端记录关联请求和脱敏错误。当前 503 的真实来源仍需同一出错机器、同一会话的失败结果核对。

## 修改的代码点

已实现：元信息与历史解耦、加载提示、错误保留、重试最新页、服务端失败日志。独立分支 codex/session-history-503，未合并、未发布、未重启当前用户服务；桌面原启动方式不变。

没实现：消除用户实际遇到的 503。需要用户提供出错的是本机还是另一台电脑，以及会话名称或链接；不需要截图。

## 验证方式

192 项单元/集成测试、6 项桌面/375px 专项、10 项现有审批与历史回归通过；类型检查和前后端构建通过。专项故障由隔离浏览器注入，证明界面在失败时的行为，不等于真实 503 已复现或解决。协议对照只读，没有获取 writer、发送模型请求或代答现有问题。
