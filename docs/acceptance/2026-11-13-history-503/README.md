# 桌面会话历史、实时输出与 503 验收

## 说明原因

已确认并修复三条独立代码路径：

1. 首屏详情与历史绑定，历史 RPC 等待时没有独立加载状态；后台刷新开始就清除错误，使 503 提示一闪而过。
2. Web 主要读取落盘历史，未将已有桌面订阅中的完整历史与实时消息用于时间线。桌面实际已产生的内容可能还没有落盘。
3. 只要一轮中存在 final_answer，界面便折叠整轮 commentary。真实桌面样本中，同一轮仍在 inProgress，较早 final_answer 后继续产生 commentary；这些新输出已经传到 Web，却被折叠隐藏。

**远端实际 503 的根因待验证。** 用户已明确域名为 eric-codex.foxhello.com，截图中的 maikoo-pay 会话不在本机索引，不能用本机其他会话替代远端验收。远端公开前端资源与 v1.0.11 发布包字节一致，不含本次修复；后台版本未验证，业务接口要求登录。本机旧实现的元信息 128～133ms、历史 857～3020ms 均成功。默认 RPC 超时为 60 秒，异常统一转为 503；尚未捕获用户这次失败，不能断定一定是超时、桌面升级或会话锁。

## 当前代码问题点

- 分页按轮数限制，不按条目或字节限制；20 轮依然包含所有工具记录。直接改 summary 会漏掉已展示的消息、文件改动与中间过程，本次保留完整历史语义。
- 实时状态虽然已有只读桌面订阅，但只用于问题面板，没有同步至消息时间线。
- 消息折叠没有区分正在运行的轮次与最终答复之后的补充消息。
- 错误在自动请求开始时消失；详情缺失时没有历史加载提示和明确重试入口。
- 原详情失败日志只有 HTTP 503 和整体响应时间，缺少对应失败原因。

## 代码错误位置

- src/client/App.tsx：loadSessionDetail、refreshCurrentSession、SessionDetailPanel、SessionTimeline.renderTurn。
- src/client/DesktopQuestionsPanel.tsx：桌面状态轮询。
- src/server/services/DesktopQuestionService.ts：桌面快照与增量订阅。
- src/server/services/SessionService.ts：readSessionDetail 的 thread/turns/list（itemsView=full）。
- src/server/services/CodexAppServerClient.ts：默认 60 秒请求超时。
- src/server/routes/sessions.ts：详情异常转换为 503。

## 修改方案

复用现有桌面 follower，读取连续的最近历史页并沿用原始分页游标；通过已有 3 秒轮询更新 Web 时间线。旧消息、实时消息按轮次和条目 ID 合并。只折叠已结束轮次最后答复之前的过程消息，运行中的进度保持展开。

首屏历史失败时仍能展示桌面内容，并使用桌面游标读取更早历史。遇到未知边界、断层或需要截断而没有对应游标时，继续使用原有完整历史接口。Manage 自己持有的会话不等待桌面订阅。

元信息与历史独立加载；失败提示保留到请求成功；失败刷新保留已有消息；服务端记录关联请求与脱敏错误。官方桌面仍照常点原图标启动，没有新增共享 app-server、修改桌面启动参数或取得 writer。

## 验证方式

197 项单元/集成、10 项桌面/375px 专项、10 项现有审批与历史回归通过；类型检查和前后端构建通过。

本机真实验收使用隔离 Web 进程、原桌面的只读 follower，无 API 模拟：冷订阅首条消息约 3.1～3.7 秒，已有订阅约 330ms。后续真实进度自动出现；读取更早历史 HTTP 200，返回 20 轮。记录中的 appearedAfterReadyMs 包含助手尚未发出新消息的等待时间，不能当作同步延迟。没有刷新页面、发送聊天输入、代答问题或执行 resume。为了查看消息，仅在 Web 关闭待回答弹窗，问题仍留给用户。

503 专项由隔离浏览器注入，证明历史接口失败时仍可展示桌面历史、更新输出、正确翻页并保留错误；不等于远端真实 503 已复现或解决。
