# Codex Manage 桌面端、内网穿透与运营后台需求文档

## 1. 文档信息

- 文档版本：V1.1
- 文档状态：需求已审核，可进入技术设计
- 审核日期：2026-07-21
- 所属项目：Codex Manage
- 目标版本：Desktop & Cloud Platform V1

## 2. 项目背景

现有 Codex Manage 已具备本地 Web 管理能力，包括 Codex 会话列表、会话详情、会话恢复、实时输出、命令展示、审批交互、模型选择、登录和 H5 页面适配。

当前产品仍以开发者自行启动 Node.js 服务的方式运行，不适合普通用户安装使用，也没有统一的公网访问、用户注册、设备管理、域名管理和商业化能力。

本次需求需要将现有 Codex Manage 扩展为可以在 macOS、Windows 上安装的桌面产品。桌面客户端内置运行环境和 cloudflared，在用户启动应用后自动建立 Cloudflare Tunnel、生成二维码，并允许用户通过手机安全访问本机 Codex Manage。

同时建设独立的云端控制服务和管理员后台，用于记录用户、设备、Tunnel、域名、套餐、订单和支付预留数据。

## 3. 已审核产品决策

以下内容已经确认，不再作为待定需求：

1. 域名策略采用双模式：试用或免费用户使用随机 Quick Tunnel，正式用户使用固定子域名和 Named Tunnel。
2. 平台主域名使用 `xmwefun.cn`，具体业务子域名按本文件规划。
3. 用户注册同时支持邮箱和手机号，注册页面默认展示邮箱方式，以减少短信成本。
4. 安装包暂不内置 Codex CLI，只检测本机 Codex CLI 是否存在并提供安装、登录引导。
5. macOS 支持 Apple Silicon 和 Intel 芯片；Windows 首期支持 x64。
6. V1 暂不接入微信、支付宝或其他真实支付渠道，只保留支付页面、接口、数据模型和权益控制能力。

## 4. 产品目标

### 4.1 用户目标

- 用户可以从官网下载 macOS 或 Windows 安装包。
- 用户不需要自行安装 Node.js 或 cloudflared。
- 用户完成安装并启动应用后，可以通过引导完成账号登录、设备注册和本机安全设置。
- 客户端可以自动启动 Codex Manage 本地服务和 Cloudflare Tunnel。
- 客户端自动展示公网访问地址和二维码。
- 用户使用手机扫码后，可以通过移动网络访问本机 Codex Manage。
- 用户可以查看当前域名、Tunnel 状态、账号、套餐和设备信息。

### 4.2 平台目标

- 平台能够记录用户注册信息。
- 平台能够记录用户安装和绑定的设备。
- 平台能够记录每台设备使用的随机地址或固定域名。
- 平台能够创建、停用和撤销正式用户的 Named Tunnel。
- 平台能够查看设备在线状态、客户端版本和最后心跳时间。
- 平台具备套餐、订阅、订单、支付和权益的数据结构。
- 管理员可以在未接入真实支付前手动为用户开通正式权益。

### 4.3 隐私目标

云端平台只管理账号、设备、域名、Tunnel 和商业化元数据，不上传以下本机内容：

- Codex 会话内容。
- 用户输入的任务和提示词。
- Codex 回复。
- 命令内容和命令输出。
- 本地项目文件和目录内容。
- Codex API Key、登录凭证或模型提供方密钥。

## 5. 产品组成

本次产品由四个部分组成：

### 5.1 桌面客户端

负责安装引导、账号登录、设备注册、本地服务管理、cloudflared 管理、二维码展示、托盘运行和本机诊断。

### 5.2 Codex Manage 本地服务

复用现有 React、Fastify 和 Codex app-server 集成能力，继续负责 Codex 会话管理和实时交互。

### 5.3 云端控制服务

负责用户认证、设备认证、Tunnel 分配、域名管理、心跳、套餐、权益和商业化数据接口。

### 5.4 运营管理后台

负责用户、设备、域名、Tunnel、套餐、订单、支付记录和审计日志管理。

## 6. 用户角色

### 6.1 普通用户

- 注册和登录平台账号。
- 安装并绑定桌面设备。
- 启动或停止本机远程访问。
- 查看和复制访问地址。
- 扫码访问本机 Codex Manage。
- 查看自己的设备、域名和套餐状态。
- 解绑或停用自己的设备。

### 6.2 平台管理员

- 查看平台数据概览。
- 管理用户、设备、域名和 Tunnel。
- 封禁或恢复用户。
- 停用设备和撤销 Tunnel Token。
- 配置套餐和权益。
- 手动开通、延期或取消订阅权益。
- 查看订单、支付占位记录和后台审计日志。

### 6.3 只读运营人员

- 查看用户、设备、域名和业务统计。
- 查看订单和订阅数据。
- 不允许修改 Tunnel、用户状态和权益。

## 7. 域名规划

建议使用以下业务域名：

| 用途 | 建议域名 |
| --- | --- |
| 云端控制 API | `codex-api.xmwefun.cn` |
| 管理员后台 | `codex-admin.xmwefun.cn` |
| 产品官网与下载页 | `codex.xmwefun.cn` |
| 正式用户设备域名 | `d-<设备短码>.xmwefun.cn` |

设备短码必须由服务端生成，不直接暴露数据库自增 ID、邮箱、手机号或完整设备 ID。

正式用户固定域名示例：

```text
d-a83k2m.xmwefun.cn
```

架构审核后，V1 统一采用 `xmwefun.cn` 下的单级子域名，避免多级子域名带来的额外证书配置和成本。如果后续改用 `*.codex.xmwefun.cn`，必须先配置能够覆盖该层级的证书。

V1 默认由平台自动生成子域名，不开放用户自由输入域名前缀，避免域名抢占、敏感词和审核问题。自定义子域名作为后续权益能力预留。

## 8. 核心业务流程

### 8.1 首次安装流程

1. 用户下载对应操作系统和 CPU 架构的安装包。
2. 用户完成安装并启动 Codex Manage。
3. 客户端生成本机设备 ID、设备密钥和本地安全配置。
4. 客户端检测 Codex CLI 是否存在、版本是否可读取、是否可以启动 app-server。
5. 用户注册或登录平台账号。
6. 用户设置本机访问密码。
7. 客户端向云端控制服务注册设备。
8. 云端根据用户权益返回 Quick Tunnel 或 Named Tunnel 模式。
9. 客户端启动本地 Codex Manage 服务。
10. 客户端启动 cloudflared 并等待公网地址可用。
11. 客户端生成公网地址和一次性扫码授权二维码。
12. 用户扫码完成手机授权并进入 Codex Manage。

### 8.2 日常启动流程

1. 客户端读取本机加密保存的设备凭证。
2. 客户端验证本地端口并启动 Codex Manage 服务。
3. 客户端向云端获取当前设备权益和 Tunnel 配置。
4. 客户端启动或恢复 cloudflared。
5. 客户端上报在线心跳和当前访问地址。
6. 客户端展示 Tunnel 在线状态、地址和二维码。

### 8.3 设备解绑流程

1. 用户在客户端或用户中心发起解绑。
2. 云端将设备状态改为已解绑。
3. 云端撤销设备访问凭证和 Named Tunnel Token。
4. 云端停用设备域名映射。
5. 客户端停止 Tunnel 并清除云端设备凭证。
6. 已授权手机登录态失效。

## 9. 桌面安装包需求

### 9.1 技术基线

桌面端建议采用 Electron，以便复用现有 Node.js、Fastify、React 和 Codex app-server 集成代码。

安装包必须包含：

- Electron 运行环境。
- Codex Manage 前端静态资源。
- Codex Manage Fastify 服务端。
- 对应操作系统和架构的 cloudflared 二进制文件。
- 本地配置、日志和升级所需目录。

安装包暂不包含 Codex CLI。

### 9.2 支持平台

| 操作系统 | 架构 | V1 要求 |
| --- | --- | --- |
| macOS | Apple Silicon / arm64 | 必须支持 |
| macOS | Intel / x64 | 必须支持 |
| Windows 10/11 | x64 | 必须支持 |
| Windows | arm64 | V1 不要求 |
| Linux | 任意 | V1 不要求 |

macOS 可以提供一个 Universal 安装包，也可以分别提供 arm64 和 x64 安装包，但下载页必须清晰标注。

### 9.3 安装与卸载

- macOS 提供 DMG 或等效图形化安装包。
- Windows 提供 EXE 安装包。
- 安装过程不要求用户使用终端。
- 应用数据和用户 Codex 会话不能因为应用升级而丢失。
- 默认卸载不得删除 `~/.codex/sessions`、Codex CLI 或用户项目文件。
- 卸载程序可以询问是否同时删除 Codex Manage 自身的账号缓存、日志和设备配置。

### 9.4 应用签名

正式公开发布前必须完成：

- macOS Developer ID 签名与 Apple Notarization。
- Windows 代码签名，降低 SmartScreen 拦截概率。

开发测试包可以暂时使用未签名版本，但必须明确标注测试用途。

## 10. 桌面客户端功能需求

### 10.1 首页

首页至少展示：

- 本地服务状态。
- Codex CLI 状态。
- Tunnel 状态。
- 公网访问地址。
- 二维码。
- 当前 Tunnel 模式。
- 当前设备名称。
- 当前套餐或权益。
- 启动、停止、重连和复制地址操作。

### 10.2 状态定义

本地服务状态：

- 未启动。
- 启动中。
- 运行中。
- 启动失败。
- 已停止。

Tunnel 状态：

- 未配置。
- 获取配置中。
- 启动中。
- 在线。
- 断线重连中。
- 已停止。
- Token 已失效。
- 启动失败。

### 10.3 系统托盘

- 用户关闭主窗口时，默认最小化到系统托盘，而不是直接停止远程访问。
- 托盘菜单至少包含打开主窗口、复制访问地址、启动或停止 Tunnel、退出应用。
- 用户明确选择退出应用时，停止本地服务和 cloudflared 子进程。

### 10.4 开机启动

- 提供“开机自动启动”设置项。
- 默认关闭，由用户主动开启。
- 开机启动后允许静默进入托盘。

### 10.5 日志与诊断

客户端应记录：

- 桌面应用启动和退出。
- 本地服务启动和退出。
- cloudflared 启动、退出和重连。
- API 请求失败摘要。
- Codex CLI 检测结果。

日志不得记录：

- 用户密码。
- 设备完整密钥。
- Tunnel Token。
- 一次性扫码授权码。
- Codex 对话和命令内容。

客户端应提供“导出诊断日志”能力，导出前必须进行敏感信息脱敏。

## 11. Codex CLI 检测与引导

### 11.1 检测项目

- 系统是否可以执行 `codex`。
- Codex CLI 版本是否可以读取。
- `codex app-server` 是否可以启动。
- Codex 是否已完成必要登录或授权。

### 11.2 未安装处理

- 应用仍允许启动并进入桌面首页。
- 明确提示“尚未安装 Codex CLI”。
- 提供安装说明和复制安装命令的入口。
- 暂不由客户端静默安装 Codex CLI。
- Codex CLI 不可用时，不允许进入会话恢复和任务交互能力，但 Tunnel 和账号诊断页面仍可使用。

### 11.3 版本处理

- 记录本机 Codex CLI 版本。
- 低于最低兼容版本时展示升级提示。
- Codex CLI 升级由用户自行完成。
- 最低兼容版本必须通过客户端配置或云端配置维护，不能散落在界面代码中。

## 12. 本地服务管理

- 桌面版默认将 Codex Manage 监听在 `127.0.0.1`，避免直接暴露局域网端口。
- 本地服务端口优先使用固定配置；端口被占用时可以选择备用端口并通知 cloudflared。
- cloudflared 只能代理当前桌面应用确认的本地服务地址。
- 本地服务异常退出后，桌面主进程应按有限次数自动重启。
- 连续启动失败时停止自动重启并展示明确错误。
- Electron 主窗口关闭不能导致本地服务意外退出。
- 桌面应用退出后不得遗留失控的 Node.js 或 cloudflared 子进程。

## 13. Cloudflare Tunnel 需求

### 13.1 Quick Tunnel 模式

Quick Tunnel 用于试用或免费权益：

- 客户端直接启动内置 cloudflared 创建 Quick Tunnel。
- 获取随机 `trycloudflare.com` 访问地址。
- 客户端将当前随机地址、设备 ID、开始时间和状态上报云端。
- 随机地址可能在应用或 Tunnel 重启后发生变化。
- 地址变化后必须更新客户端二维码和后台记录。
- Quick Tunnel 创建失败时展示错误并提供重试。

### 13.2 Named Tunnel 模式

Named Tunnel 用于正式权益：

- 云端为每台有效设备创建独立的 remotely-managed Tunnel。
- 云端为设备分配固定子域名。
- 云端向客户端发放仅限该 Tunnel 使用的 Token。
- Cloudflare 账户级 API Token 只能保存在云端服务中。
- 客户端不得获得 Cloudflare 账户级权限。
- 客户端使用设备专属 Tunnel Token 启动 cloudflared。
- 应用重启或网络重连后，固定域名保持不变。
- 设备解绑、用户封禁或权益失效后，云端可以撤销 Token 和域名路由。

### 13.3 Tunnel 进程管理

- 启动 cloudflared 时不打开额外终端窗口。
- 记录进程 PID、启动时间、退出码和脱敏错误摘要。
- 异常退出后采用退避策略自动重连。
- 网络断开期间不能无限高频重启。
- 用户手动停止后不得自动重新启动，除非用户再次操作或应用重启策略明确要求。
- 客户端升级时必须正确停止旧 cloudflared 进程。

## 14. 二维码与手机授权

### 14.1 二维码内容

二维码不能只包含长期有效的管理密码，也不能在 URL 中放置设备密钥或 Tunnel Token。

建议二维码采用以下结构：

```text
https://<设备访问域名>/#/pair?code=<一次性授权码>
```

使用 URL Fragment 的目的，是避免授权码在首次页面请求时直接进入代理访问日志。前端加载后再通过受控接口提交授权码。

### 14.2 一次性授权码

- 由本机 Codex Manage 服务生成。
- 使用安全随机数生成。
- 默认有效期不超过 5 分钟。
- 成功使用一次后立即失效。
- 连续失败达到阈值后自动失效。
- 客户端支持手动刷新二维码，使旧授权码立即失效。
- 授权码不得上传到云端控制后台。

### 14.3 手机授权流程

1. 手机扫码打开设备公网地址。
2. 页面读取 Fragment 中的一次性授权码。
3. 页面向该设备本地服务提交授权码。
4. 本地服务验证授权码、有效期和使用状态。
5. 验证成功后创建安全登录 Cookie。
6. 页面清理地址栏中的授权码。
7. 用户进入 Codex Manage 页面。

### 14.4 后续访问

- 授权成功后可以保留合理期限的登录态。
- 用户可以在桌面客户端查看并撤销已授权手机会话。
- 修改本机访问密码、解绑设备或执行“退出所有设备”后，已授权手机登录态全部失效。
- 用户也可以使用本机访问密码手动登录。

## 15. 用户注册与认证

### 15.1 注册方式

V1 同时支持：

- 邮箱验证码或邮箱验证链接注册。
- 手机短信验证码注册。

注册页面默认打开邮箱注册页签，手机号注册作为可切换方式展示。

### 15.2 邮箱注册

- 输入邮箱地址。
- 完成人机校验或基础防刷校验。
- 发送验证码或验证链接。
- 验证成功后设置密码或创建无密码登录凭证。
- 邮件验证码需要有效期和发送频率限制。

### 15.3 手机号注册

- 支持配置的国家或地区号，V1 至少支持中国大陆 `+86`。
- 发送短信验证码。
- 验证码需要有效期、错误次数和发送频率限制。
- 短信服务商通过服务端适配层接入，具体厂商可以在详细设计阶段确定。

### 15.4 账号关联

- 同一账号可以同时绑定邮箱和手机号。
- 已存在账号绑定新邮箱或手机号时必须进行验证。
- 不允许仅凭相同手机号或邮箱未经验证自动合并账号。
- 管理后台可以查看绑定状态，但不展示完整敏感信息。

### 15.5 登录与 Token

- 桌面客户端登录后获得短期 Access Token 和可轮换的 Refresh Token。
- Refresh Token 保存在操作系统安全存储中。
- macOS 优先使用 Keychain。
- Windows 优先使用 Credential Manager 或等效安全存储。
- Token 失效时要求重新登录，不能回退为硬编码公共 Token。

## 16. 设备管理

### 16.1 设备信息

每台设备至少记录：

- 设备 ID。
- 设备短码。
- 所属用户。
- 用户自定义设备名称。
- 操作系统。
- CPU 架构。
- 客户端版本。
- Codex CLI 版本。
- 注册时间。
- 最后在线时间。
- 当前状态。
- Tunnel 模式。
- 当前域名或 Quick Tunnel 地址。

不得上传设备序列号、MAC 地址等不必要的硬件唯一标识。

### 16.2 设备状态

- 待激活。
- 在线。
- 离线。
- 已解绑。
- 已停用。
- 已封禁。

### 16.3 心跳

- 在线客户端定时上报心跳。
- 心跳包含设备 ID、客户端版本、Tunnel 状态和脱敏错误码。
- 默认心跳周期建议为 60 秒，最终值在详细设计中确定。
- 连续多个心跳周期未收到上报后标记为离线。
- 云端离线状态只代表客户端未上报，不代表删除设备或 Tunnel。

### 17.1 V1 范围

## 21. 安全要求

### 21.1 公网访问安全

- 桌面版本不得继续使用固定公共默认密码直接开放公网访问。
- 首次使用必须设置本机访问密码，或使用扫码一次性授权完成设备登录。
- 登录、验证码和扫码授权接口必须限流。
- 公网 Cookie 必须设置 `HttpOnly` 和 `Secure`。
- 应根据跨站访问方案设置合理的 `SameSite`。
- 所有修改类接口需要 CSRF 防护或等效的同源 Token 机制。
- WebSocket 连接必须进行登录态校验。
- 退出所有设备后，WebSocket 和现有 Cookie 同时失效。

### 21.2 云端认证安全

- 密码使用可靠的自适应哈希算法保存。
- 验证码不得明文长期保存。
- Access Token 使用短有效期。
- Refresh Token 支持轮换和撤销。
- 设备凭证与用户登录凭证分离。
- Cloudflare 账户 API Token 只允许云端 Tunnel 服务访问。

### 21.3 本地密钥安全

- macOS 使用 Keychain 保存 Refresh Token 和设备密钥。
- Windows 使用 Credential Manager 或等效安全存储。
- 本地普通配置文件中不得出现明文账号密码、Cloudflare API Token 或设备完整密钥。

### 21.4 Codex 高风险能力保护

Codex Manage 可以执行命令和修改文件，因此：

- 未登录用户不能读取会话和运行状态。
- 审批操作必须由有效登录态执行。
- 一次性扫码授权成功前不能调用 Codex 管理接口。
- 管理后台不能通过云端 API 远程执行用户本机 Codex 命令。
- 平台不得设计绕过用户本机审批的远程控制接口。

## 22. 非功能需求

### 22.1 稳定性

- 网络中断后 Tunnel 可以自动恢复。
- 云端控制服务暂时不可用时，本地 Codex Manage 仍可通过 localhost 使用。
- Quick Tunnel 模式下，云端上报失败不能阻止本地 Tunnel 建立。
- Named Tunnel Token 仍有效时，短时云端故障不能强制中断已经建立的 Tunnel。
- 本地服务和 Tunnel 状态必须分别展示，避免将两类故障混为一类。

### 22.2 性能

- 客户端空闲时不得持续占用大量 CPU。
- 心跳和状态刷新不得形成高频网络请求。
- 桌面主窗口关闭到托盘后，渲染进程资源应合理释放。
- 二维码和地址变化应在客户端状态更新后及时刷新。

### 22.3 可维护性

- cloudflared 管理封装为独立模块。
- Cloudflare API 调用封装为云端独立适配层。
- 邮件和短信服务使用可替换适配层。
- 支付渠道使用可替换适配层。
- 客户端、云端和后台共享统一的接口类型和业务错误码。

### 22.4 可观测性

- 云端记录 API 错误率、Tunnel 创建失败率和心跳延迟。
- 客户端错误使用稳定错误码，方便后台统计。
- 敏感信息在日志和监控平台中统一脱敏。

## 25. 验收标准

### 25.1 安装验收

- macOS Apple Silicon 可以正常安装、启动和卸载。
- macOS Intel 可以正常安装、启动和卸载。
- Windows 10/11 x64 可以正常安装、启动和卸载。
- 未安装 Node.js 和 cloudflared 的电脑可以直接运行客户端。
- 升级和卸载不删除 Codex 会话和用户项目文件。

### 25.2 Codex 检测验收

- 已安装 Codex CLI 时可以正确展示版本和可用状态。
- 未安装时展示明确引导，客户端不会直接崩溃。
- app-server 不可用时，展示独立诊断信息。

### 25.3 Quick Tunnel 验收

- 免费或试用设备可以成功创建 Quick Tunnel。
- 客户端可以识别并展示随机地址。
- 手机使用非本机局域网网络扫码可以访问。
- Tunnel 地址变化后二维码和后台记录同步更新。

### 25.4 Named Tunnel 验收

- 管理员可以为用户开通正式权益。
- 正式用户设备可以获得固定的 `d-<设备短码>.xmwefun.cn` 子域名。
- 应用、电脑或网络重启后固定域名保持不变。
- 客户端不包含 Cloudflare 账户级 API Token。
- 设备解绑或被停用后，原 Token 和域名访问失效。

### 25.5 扫码安全验收

- 二维码使用一次性授权码。
- 授权码过期后不能登录。
- 授权码使用一次后不能再次使用。
- 刷新二维码后旧二维码失效。
- 二维码中不包含本机密码、设备密钥或 Tunnel Token。
- 用户可以撤销已授权手机会话。

### 25.6 用户和后台验收

- 用户可以使用邮箱注册和登录。
- 用户可以使用手机号注册和登录。
- 注册页面默认展示邮箱方式。
- 后台可以查看用户、设备、域名、Tunnel 模式和在线状态。
- 后台可以封禁用户、停用设备和撤销 Tunnel Token。
- 后台无法查看用户 Codex 会话、提示词、命令和项目文件。

### 25.7 套餐与支付预留验收

- 客户端可以查看套餐、当前权益和到期时间。
- 支付入口明确显示尚未开放。
- 后台可以配置套餐和权益。
- 管理员可以人工开通正式权益并设置到期时间。
- 系统存在订单、支付和订阅数据模型，但不会发生真实扣款。

## 27. 主要风险

### 27.1 公网暴露风险

Codex Manage 具有本机命令和文件操作能力。公网版本必须先完成新的认证、扫码授权、限流和 Cookie 安全改造，不能直接将当前开发版默认密码服务暴露到 Tunnel。

### 27.2 Cloudflare 平台依赖

Quick Tunnel 和 Named Tunnel 均依赖 Cloudflare 服务。产品必须区分本地服务故障、客户端网络故障、Cloudflare 故障和平台控制服务故障。

### 27.3 安装包体积

Electron、Node.js 和 cloudflared 会增加安装包体积，需要在构建阶段进行资源裁剪和压缩，但不能以牺牲可维护性为代价。

### 27.4 双架构发布

macOS 同时支持 arm64 和 x64，要求构建流程管理不同架构的 cloudflared 和原生依赖，发布前必须在真实设备或对应环境验证。

### 27.5 短信成本与滥用

手机号注册会产生短信费用。邮箱作为默认注册方式，同时对短信接口增加频率限制、人机校验、IP 限制和账号级限制。
