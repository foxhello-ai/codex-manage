# 问题反馈与自动上报需求变更单

| 项目 | 内容 |
| --- | --- |
| 变更编号 | `CM-CR-20260725-002` |
| 日期 | 2026-07-25 |
| 状态 | 已审核，可进入技术设计 |
| 影响范围 | macOS x64、macOS arm64、Windows x64 桌面客户端；云端控制服务；运营管理后台 |
| 目标版本 | 下一个桌面安装包版本 |
| 关联问题 | 当前没有问题反馈入口，客户故障只能通过人工传日志或远程排查，无法形成问题闭环 |

## 1. 变更背景

当前 Codex Manage 已提供“导出诊断日志”，但没有内置问题反馈和问题自动上报入口。客户遇到 Windows 本地服务不可用、远程通道失败、会话展示异常或模型切换异常时，需要人工导出日志并通过外部渠道发送，定位链路长且容易丢失上下文。

本次变更要求建立“桌面端采集、云端控制服务接收、运营后台处理”的完整问题闭环：

- 桌面端提供用户主动上报入口。
- 桌面端自动上报崩溃、不可用、优化和需求类问题。
- 需要本地运行信息的问题，必须随问题一起上报到后端，不能只保存在本地日志。
- 后端统一存储问题、运行快照、脱敏日志摘要、处理状态和审计记录。
- 管理后台提供问题列表、详情、状态流转、优先级和处理备注。

## 2. 目标

- 用户可以在桌面端一键提交问题，不需要手工找到日志文件。
- 主动上报的问题优先级最高，进入后台后默认置顶处理。
- 自动上报按问题类型和影响程度分级，区分崩溃、不可用、普通缺陷、优化和需求。
- 上报数据包含足够定位问题的本地运行信息，包括版本、平台、Codex CLI、app-server、本地服务、Tunnel、账号权益和最近脱敏诊断。
- 上报过程不泄露 Codex 会话内容、用户项目文件、命令内容、密钥、Token 或扫码授权码。
- 客户离线时问题可先进入本地待发送队列，网络恢复后自动补发。
- 管理后台可以按用户、设备、版本、平台、严重级别、问题类型和状态筛选。

## 3. 非目标

- 不接入第三方客服系统或 IM 工单系统，V1 先在自有控制服务和管理后台闭环。
- 不自动上传完整日志文件、截图、Codex 对话内容或项目文件。
- 不让用户手动填写后端严重级别；主动上报默认最高优先级，后台人员可二次分诊。
- 不自动修复问题；本变更只负责发现、上报、存储和处理流程。
- 不替代 crash dump 系统；V1 先记录崩溃摘要、退出码、阶段和运行快照。

## 4. 问题来源

| 来源 | 说明 | 默认优先级 |
| --- | --- | --- |
| `manual` | 用户在桌面端主动点击“反馈问题/报告问题”提交 | `P0_MANUAL` |
| `auto_crash` | 主进程、渲染进程、本地服务、app-server 或 cloudflared 非预期崩溃 | `P1_CRASH` |
| `auto_unavailable` | 核心能力不可用，例如本地服务无法启动、app-server not ready、Tunnel 无法上线、登录或设备认证不可用 | `P2_UNAVAILABLE` |
| `auto_defect` | 功能异常但有降级或重试路径，例如云端 500/503 重试后成功、会话读取部分失败 | `P3_DEFECT` |
| `auto_optimization` | 性能、稳定性或体验优化线索，例如启动耗时过长、重试次数异常、后台请求频繁失败后恢复 | `P4_OPTIMIZATION` |
| `auto_requirement` | 产品需求线索，例如用户多次触发未实现功能、空状态中高频点击帮助入口 | `P5_REQUIREMENT` |

## 5. 问题级别

| 级别 | 名称 | 触发条件 | 处理要求 |
| --- | --- | --- | --- |
| `P0_MANUAL` | 主动上报 | 用户主动提交的问题、建议或需求 | 后台最高优先级，默认置顶；必须人工确认和分诊 |
| `P1_CRASH` | 崩溃 | 应用进程、渲染进程、本地服务、app-server、cloudflared 非预期退出或连续崩溃 | 必须进入故障跟踪，优先确认版本和平台影响面 |
| `P2_UNAVAILABLE` | 不可用 | 核心链路不可用，包括本地服务不可用、Codex app-server not ready、远程通道不可用、设备认证失败 | 必须关联设备和运行快照，优先排查发布阻断 |
| `P3_DEFECT` | 功能异常 | 功能失败但应用仍可使用，或自动重试后恢复 | 可合并去重，按版本和影响范围排期 |
| `P4_OPTIMIZATION` | 优化 | 性能、稳定性、提示文案或交互体验问题 | 进入优化池，按频次和影响范围排序 |
| `P5_REQUIREMENT` | 需求 | 自动识别的需求线索或低风险产品建议 | 进入需求池，不按故障 SLA 处理 |

规则：

- 主动上报级别最高，即使用户选择“优化”或“需求”，初始优先级仍为 `P0_MANUAL`。
- 自动上报不能生成 `P0_MANUAL`。
- 后台可以在分诊后调整级别，但必须保留原始来源和初始级别。
- 自动问题必须根据 `fingerprint` 去重，避免同一设备短时间刷屏。

## 6. 上报内容

### 6.1 通用字段

- `reportId`：服务端生成的问题 ID。
- `source`：`manual` 或自动来源。
- `level`：问题级别。
- `category`：`crash`、`unavailable`、`defect`、`optimization`、`requirement`。
- `title`：问题标题。
- `description`：用户描述或自动摘要。
- `userId`：登录用户 ID，未登录时为空。
- `deviceId`：已绑定设备 ID，未绑定时为空。
- `clientVersion`：桌面端版本。
- `platform`、`arch`、`osVersion`：系统环境。
- `channel`：发布渠道，例如 `stable`。
- `createdAt`：客户端发生时间。
- `receivedAt`：服务端接收时间。
- `fingerprint`：自动问题去重指纹。

### 6.2 本地运行信息

需要本地运行信息的问题，必须随上报一起发送到后端，至少包含：

- Codex CLI 检测状态、路径类型和版本。
- `codex app-server` 状态、PID、初始化状态和最近错误。
- 本地 Web 服务状态、端口、URL、最近错误。
- cloudflared 状态、模式、公开域名、最近错误、重连次数。
- 当前账号登录状态、套餐/权益摘要、Named Tunnel 状态。
- 开机启动状态、托盘运行状态、是否隐藏启动。
- 最近一次自动更新状态和版本信息。
- 最近 5 分钟脱敏诊断日志摘要。
- 最近 20 条关键事件计数，例如启动失败、重试、认证失败、网络失败。

禁止上报：

- 用户密码、本地访问密码、刷新 Token、设备密钥、Tunnel Token。
- 一次性扫码授权码。
- Codex 对话内容、用户输入、模型回复。
- 命令内容、命令输出、项目文件路径全文和文件内容。
- 完整公网访问 URL 中的敏感查询参数。

### 6.3 主动上报附加字段

- 用户填写的问题描述。
- 用户选择的问题类型：故障、不可用、优化、需求、其他。
- 用户可选联系方式。
- 是否允许附带脱敏诊断摘要。
- 是否允许客服根据设备 ID 查看近期心跳和 Tunnel 状态。

V1 默认不上传截图；后续如支持截图，必须单独让用户确认。

## 7. 自动上报触发条件

### 7.1 崩溃

- Electron 主进程异常退出或未捕获异常。
- Renderer crash、unresponsive 或 preload 初始化失败。
- 本地服务子进程异常退出。
- `codex app-server` 非用户主动停止退出。
- cloudflared 非用户主动停止退出且重试达到阈值。

### 7.2 不可用

- 本地服务连续启动失败。
- `Codex app-server is not ready` 连续出现或持续超过阈值。
- Codex CLI 检测失败且用户已完成安装引导。
- 远程通道连续启动失败。
- Named Tunnel 权益存在但无法获取专属域名或 Token。
- 设备认证、刷新或心跳连续失败。

### 7.3 功能异常

- 会话列表或详情读取失败。
- 模型目录加载失败。
- 模型切换失败。
- 自动更新检查、下载或安装失败。
- 云端控制 API 临时错误重试后恢复。

### 7.4 优化

- 启动耗时超过阈值。
- 本地服务或 Tunnel 重试次数超过阈值但最终成功。
- 请求延迟持续超过阈值。
- 日志中出现高频重复警告。

### 7.5 需求

- 用户高频点击未实现入口。
- 用户在空状态或错误状态中多次点击帮助/反馈。
- 用户多次触发同一类受限能力，例如服务商热切换、自动更新、移动端桌面入口。

## 8. 后端需求

### 8.1 API

- `POST /v1/issue-reports/manual`：接收用户主动上报。
- `POST /v1/issue-reports/auto`：接收客户端自动上报。
- `GET /v1/issue-reports/:id`：用户查看自己提交的问题状态。
- `GET /admin/issue-reports`：管理后台查询问题列表。
- `GET /admin/issue-reports/:id`：管理后台查看问题详情。
- `PATCH /admin/issue-reports/:id`：管理后台更新状态、级别、负责人、处理备注和关联故障编号。

### 8.2 数据模型

建议新增：

- `issue_reports`：问题主表。
- `issue_report_snapshots`：运行快照表。
- `issue_report_events`：状态流转和处理审计表。
- `issue_report_dedup`：自动问题去重和聚合表。

核心字段：

- 问题主表：`id`、`source`、`level`、`category`、`title`、`description`、`user_id`、`device_id`、`client_version`、`platform`、`arch`、`fingerprint`、`status`、`assignee`、`linked_incident_id`、`created_at`、`updated_at`。
- 快照表：`issue_report_id`、`runtime_snapshot_json`、`diagnostic_excerpt_json`、`redaction_version`、`created_at`.
- 审计表：`issue_report_id`、`actor_type`、`actor_id`、`action`、`before_json`、`after_json`、`created_at`.
- 去重表：`fingerprint`、`first_report_id`、`last_report_id`、`count`、`first_seen_at`、`last_seen_at`.

### 8.3 后端处理规则

- 自动上报按 `fingerprint + clientVersion + platform + arch` 聚合。
- 同一设备同一指纹 30 分钟内只创建一条主问题，后续只增加计数和最近时间。
- 主动上报不参与自动去重，必须生成独立问题记录。
- 后端必须校验用户和设备权限，设备只能上报自己的运行信息。
- 未登录用户只能上报匿名崩溃摘要，不允许关联设备权益数据。
- 后端必须对上报频率、单条大小和日志摘要长度做限制。
- 所有敏感字段进入存储前必须再次脱敏。

## 9. 桌面端需求

### 9.1 主动上报入口

- 首页增加“反馈问题”入口。
- 设置页增加“反馈问题”和“查看已提交问题”入口。
- 托盘菜单增加“反馈问题”入口。
- 关键错误提示中增加“上报该问题”按钮。

### 9.2 主动上报表单

表单字段：

- 问题类型：故障、不可用、优化、需求、其他。
- 问题描述：必填。
- 复现步骤：可选。
- 期望结果：可选。
- 联系方式：可选。
- 勾选项：附带脱敏运行信息和诊断摘要。

提交后必须展示问题编号，便于客服和客户对账。

### 9.3 自动上报控制

- 崩溃和不可用自动上报默认开启。
- 优化和需求类自动上报默认开启，但必须在设置页允许关闭。
- 用户关闭自动上报后，主动上报仍可使用。
- 自动上报失败时进入本地待发送队列，队列大小必须有上限。

### 9.4 本地队列

- 离线或云端不可达时，本地保存待发送问题。
- 待发送内容必须已经脱敏。
- 队列按时间和级别排序，优先补发 `P1_CRASH` 和 `P2_UNAVAILABLE`。
- 队列超过上限时，保留最高级别和最新问题。
- 用户可以清空待发送问题。

## 10. 管理后台需求

- 提供问题列表页面。
- 支持按来源、级别、类型、状态、版本、平台、架构、用户、设备和时间筛选。
- 支持查看运行快照和脱敏诊断摘要。
- 支持状态流转：`new`、`triaged`、`in_progress`、`waiting_user`、`resolved`、`closed`、`ignored`。
- 支持修改级别、负责人、处理备注和关联故障编号。
- 支持查看自动聚合计数、首次出现时间和最近出现时间。
- 支持从问题创建故障记录或关联已有故障记录。
- 主动上报问题必须在列表中置顶或单独筛选。

## 11. 隐私与安全要求

- 上报前客户端必须脱敏，入库前后端必须二次脱敏。
- 默认不得上传 Codex 会话正文、命令内容、命令输出和项目文件内容。
- 项目路径只允许上传脱敏后的工作区标识，例如 hash 或最后一级目录名。
- 公网访问地址只允许上传 hostname，不上传查询参数。
- Token、设备密钥、扫码授权码必须被固定占位符替换。
- 用户可在设置页查看自动上报开关和隐私说明。
- 管理后台查看问题详情必须记录审计日志。

## 12. 审核结论

本变更可执行，且应优先于更大范围的客服系统建设。原因：

1. 当前客户故障高度依赖人工传日志，影响 Windows 远程排障效率。
2. 主动上报入口能直接收集用户描述和运行快照，优先级最高符合客服处理逻辑。
3. 自动上报能提前发现崩溃和不可用问题，避免只在客户反馈后被动处理。
4. 所有需要本地运行信息的问题都进入后端统一存储，有利于版本、设备、平台维度聚合分析。
5. 通过严格脱敏、限流、去重和权限校验，可以控制隐私和后台噪音风险。

审核结论：需求范围清晰，建议进入技术设计与实现。

## 13. 验收标准

1. 用户可以从首页、设置页、托盘和关键错误提示进入主动上报。
2. 主动上报成功后返回问题编号，并在后台显示为 `P0_MANUAL`。
3. 自动崩溃上报生成 `P1_CRASH` 问题，并包含脱敏运行快照。
4. 自动不可用上报生成 `P2_UNAVAILABLE` 问题，并包含本地服务、app-server 和 Tunnel 状态。
5. 自动优化和需求上报可以在设置页关闭。
6. 离线时问题进入本地队列，网络恢复后自动补发。
7. 后端能按指纹聚合同类自动问题，主动上报不被自动合并。
8. 管理后台可筛选、查看、分诊、备注和关闭问题。
9. 上报内容不包含密码、Token、扫码授权码、Codex 对话、命令输出和项目文件内容。
10. macOS x64、macOS arm64 和 Windows x64 均通过真实安装包上报验证。
